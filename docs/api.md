# API and message contracts

| API | Interactive docs | Machine-readable spec |
|---|---|---|
| Gateway (public entry point) | http://localhost:8080/docs.html (Swagger UI) | [`gateway/src/main/resources/webroot/openapi.yaml`](../gateway/src/main/resources/webroot/openapi.yaml), served at http://localhost:8080/openapi.yaml |
| Integration service (read API, direct) | http://localhost:8081/swagger-ui.html | Generated by springdoc from annotations at http://localhost:8081/v3/api-docs |

The gateway spec is written by hand (contract first). The Spring spec is generated from the code (code first), so it cannot drift from the implementation. Both use RFC 9457 `application/problem+json` for errors.

## Authentication

```bash
# Machine client (client credentials)
TOKEN=$(scripts/get-token.sh partner)
# User tokens (password grant, enabled for scripts only)
TOKEN=$(scripts/get-token.sh alice)     # orders-read + orders-write
TOKEN=$(scripts/get-token.sh bob)       # orders-read
```

In Swagger UI, click **Authorize** and paste the token.

## Gateway endpoints (summary)

| Method | Path | Role | Result |
|---|---|---|---|
| POST | `/api/orders` | `orders-write` | `202 {orderId, status, statusUrl}`, plus `Location` and `X-RateLimit-*` headers |
| GET | `/api/orders?status=&customerId=&limit=` | `orders-read` | Processed orders, newest first |
| GET | `/api/orders/{orderId}` | `orders-read` | `200` order, or `404` while not processed or if dead-lettered |
| GET | `/api/customers` | `orders-read` | Customers with tier and credit limit |
| GET | `/api/fx-rates` | `orders-read` | Rates per 1 USD, with `source` (`seed` or `frankfurter`) |
| GET | `/api/events` | `orders-read` | `text/event-stream` with event types `processed`, `dead-letter`, `invalid` |
| GET | `/api/me` | any | Username, roles, token expiry |
| GET | `/login`, `/logout`, `/callback` | none | Browser OIDC flow |
| GET | `/health` | none | `{"status":"UP"}` |

Example:

```bash
curl -s -X POST http://localhost:8080/api/orders \
  -H "Authorization: Bearer $(scripts/get-token.sh alice)" -H 'Content-Type: application/json' \
  -d '{"customerId":"C-100","product":"Widget","quantity":2,"amount":120.50,"currency":"EUR","priority":"NORMAL"}'
# {"orderId":"7d9b...","status":"ACCEPTED","statusUrl":"/api/orders/7d9b..."}

curl -s http://localhost:8080/api/orders/7d9b... -H "Authorization: Bearer $(scripts/get-token.sh alice)" | jq
```

## Kafka topics

| Topic | Partitions | Key | Producer | Consumers | Value |
|---|---|---|---|---|---|
| `orders.raw` | 3 | `customerId` | NiFi | Camel `order-intake` (group `integration-service`) | Inbound order (below) |
| `orders.processed` | 3 | `customerId` | Camel | Gateway (group `gateway-<host>`) | Processed order (below) |
| `orders.raw.DLT` | 1 | original key | Camel | Gateway; operators | Original `orders.raw` value, unchanged, plus error headers |
| `orders.invalid` | 1 | NiFi filename | NiFi | Gateway; operators | The rejected record as received |
| `fx.rates` | 1 (compacted) | `USD` | NiFi | Camel `fx-rates` (group `integration-service-fx`) | Frankfurter response |

### `orders.raw` (inbound order)
```json
{
  "orderId": "2f6c1c8e-5a8e-4d38-9a51-2a8c1f0f3a10",
  "customerId": "C-100",
  "product": "Widget",
  "quantity": 2,
  "amount": 120.50,
  "currency": "EUR",
  "priority": "NORMAL",
  "source": "web-ui",
  "submittedBy": "alice",
  "receivedAt": "2026-10-07T17:29:29.981Z"
}
```

Field rules (enforced by Camel; violations go to the DLT):

| Field | Rule |
|---|---|
| `orderId` | Required. Must be a UUID. |
| `customerId` | Required. Must exist in `customers`. |
| `product` | Required. |
| `quantity` | Required, greater than 0. |
| `amount` | Required, greater than 0. |
| `currency` | Defaults to `USD`. Must exist in `fx_rates`. |
| `priority` | `HIGH` or `NORMAL`. Defaults to `NORMAL`. |
| `receivedAt` | ISO-8601. Defaults to the time of processing. |

File-drop records arrive with every field as a string (CSV header-derived schema). Jackson coerces the numeric ones.

### `orders.processed` (processed order)
The inbound fields plus:
```json
{
  "customerName": "Acme Corp",
  "customerTier": "GOLD",
  "fxRate": 0.894690,
  "amountUsd": 134.68,
  "status": "APPROVED",
  "lane": "EXPRESS",
  "processedAt": "2026-10-07T17:29:30.090Z"
}
```

| Field | Values |
|---|---|
| `status` | `APPROVED` or `REJECTED` |
| `lane` | `EXPRESS` (HIGH priority or GOLD customer), `STANDARD`, or `NONE` (rejected) |
| `reason` | Set only when `REJECTED` (credit limit). Omitted from the JSON when null. |

### `orders.raw.DLT` headers
| Header | Example |
|---|---|
| `x-error-type` | `UnknownCustomerException`, `InvalidOrderException`, `JsonParseException`, `CannotCreateTransactionException` |
| `x-error-message` | `Unknown customer C-999` |
| `x-source-topic` | `orders.raw` |

### `fx.rates`
```json
{"amount": 1.0, "base": "USD", "date": "2026-10-07", "rates": {"EUR": 0.89469, "GBP": 0.75731, "INR": 96.73}}
```

## Partner CSV format (file drop)

Files must end in `.csv` and be placed in `./data/inbox/`. Write the file under a dot-prefixed temporary name and rename it when complete; NiFi ignores hidden files.

```csv
orderId,customerId,product,quantity,amount,currency,priority,source,submittedBy,receivedAt
2b1e...,C-100,Bracket,3,30.00,GBP,NORMAL,file-drop,partner-sftp,2026-10-07T10:00:00Z
```
